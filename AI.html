1The big picture

You have categorical variables (vaccinations, influenza yes/no, postal code, house type…) and you count how many people fall into each combination. That gives a contingency table. The question is always the same: how are these variables related? Are they independent? Independent once we control for a third variable? Does the association change across groups?

Core idea: treat every cell count as a Poisson-distributed response $Y_i$, and model $\log E(Y_i)$ linearly with the variables as factors. That's an ordinary Poisson GLM (glm(Freq ~ ..., family = poisson)). Each question about relationships turns into "which interaction terms do I need?"

2Tables and the multinomial distribution

Notation for a two-way table (X with $I$ rows, Z with $J$ columns):

  • $Y_{ij}$ = observed count in cell $(i,j)$
  • $\pi_{ij} = P(X=i, Z=j)$ = cell probability
  • $\lambda_{ij} = E(Y_{ij})$ = expected count. With fixed total $n$: $\lambda_{ij} = n\pi_{ij}$
  • A dot means "sum over that index": $Y_{i\cdot} = \sum_j Y_{ij}$ (row total), $Y_{\cdot j}$ (column total)

If we sample a fixed number $n$ of people and drop each into a cell, the whole vector of counts is multinomial:

$$P(Y_1=y_1,\dots,Y_K=y_K)=\frac{n!}{y_1!\cdots y_K!}\prod_{i=1}^K \pi_i^{y_i},\qquad E(Y_i)=n\pi_i .$$
Think of it as: the multinomial is the binomial with more than two outcomes. The counts are not independent, because they must add up to $n$. If one cell gets more, another gets less.

In R, a table becomes a data frame with one row per cell and a Freq column (as.data.frame(tbl)). That's the format the GLM needs.

A 3-way table has variables with 2, 3 and 2 levels. How many rows does as.data.frame(tbl) have?
$K = 2\cdot 3\cdot 2 = 12$ rows, one per cell. That's the Boliga example: sold within 90 days (2) × postal code (3) × house type (2).

3The Poisson trick

This is the most important argument in the lecture, so we go slowly. Keep one question in mind the whole way: "why am I allowed to fit a Poisson model when my data are really multinomial?" By the end you should be able to answer it in two sentences.

3.1 Why we need a trick

The real data model is multinomial: $n$ is fixed, and the counts share it out between the cells. A log-linear model for the probabilities has to look like this:

$$\pi_i=\frac{e^{x_i'\beta}}{\sum_{j=1}^K e^{x_j'\beta}}.$$

Because of the denominator, which forces $\sum\pi_i=1$, every $\pi_i$ depends on every $\beta$. The likelihood is messy, and R's glm() has no multinomial family. The Poisson model has none of this: independent cells, each with its own $\lambda_i=e^{\beta_0+x_i'\beta}$, and no constraint. It's an ordinary GLM.

Goal: fit the easy Poisson model, and prove it gives the same estimates and tests as the hard multinomial model.

3.2 Building block 1: a sum of independent Poissons is Poisson

$$Y_i\sim\text{Poisson}(\lambda_i)\text{ independent}\quad\Longrightarrow\quad N=Y_1+\dots+Y_K\sim\text{Poisson}(\lambda_\cdot),\qquad\lambda_\cdot=\lambda_1+\dots+\lambda_K .$$

Intuitively, if calls arrive on $K$ independent phone lines, the total number of calls is also a "random arrivals" count, with the rates added up. The important part for us: the distribution of $N$ depends only on $\lambda_\cdot$, not on how the rate is split between the cells.

3.3 Building block 2: given the total, the counts are multinomial

Take numbers $y_1,\dots,y_K$ with $\sum y_i=n$. By the definition of conditional probability:

$$P(Y=y\mid N=n)=\frac{P(Y=y,\;N=n)}{P(N=n)}=\frac{P(Y=y)}{P(N=n)} .$$

The numerator doesn't need "$N=n$" because $N$ is computed from $Y$. If $Y=y$, then automatically $N=\sum y_i=n$. Now insert the Poisson probabilities:

$$=\frac{\displaystyle\prod_{i=1}^K\frac{\lambda_i^{y_i}e^{-\lambda_i}}{y_i!}}{\displaystyle\frac{\lambda_\cdot^{\,n}e^{-\lambda_\cdot}}{n!}} =\frac{n!}{y_1!\cdots y_K!}\cdot\frac{\lambda_1^{y_1}\cdots\lambda_K^{y_K}}{\lambda_\cdot^{\,n}}\cdot\underbrace{\frac{e^{-(\lambda_1+\dots+\lambda_K)}}{e^{-\lambda_\cdot}}}_{=1}.$$

Since $n=y_1+\dots+y_K$, we can write $\lambda_\cdot^{\,n}=\lambda_\cdot^{y_1}\cdots\lambda_\cdot^{y_K}$ and pair one copy with each factor:

$$P(Y=y\mid N=n)=\frac{n!}{y_1!\cdots y_K!}\left(\frac{\lambda_1}{\lambda_\cdot}\right)^{y_1}\cdots\left(\frac{\lambda_K}{\lambda_\cdot}\right)^{y_K}.$$

This is the multinomial probability function with $\pi_i=\lambda_i/\lambda_\cdot$. Notice: this conditional distribution depends only on the shares $\lambda_i/\lambda_\cdot$, not on how large the total rate is.

3.4 Why the likelihood can be factorised

There are two separate reasons. The first one is always true. The second one is what's special about the Poisson model.

(a) The split itself is just the multiplication rule, and holds for any distribution. For any events, $P(A\cap B)=P(B)\,P(A\mid B)$. Use $A=\{Y=y\}$ and $B=\{N=n\}$. Since $A\subseteq B$ (as in 3.3), $A\cap B=A$:

$$P(Y=y)=P(N=n)\cdot P(Y=y\mid N=n).$$

In words, the probability of seeing these exact counts = (probability of this total) × (probability of this split, given the total). That's true for any model of counts. On its own, it gives us nothing.

(b) What's special about Poisson: each factor depends on its own parameter. From 3.2, $P(N=n)$ depends only on $\lambda_\cdot$. From 3.3, $P(Y=y\mid N=n)$ depends only on $\pi=(\lambda_1/\lambda_\cdot,\dots,\lambda_K/\lambda_\cdot)$. So if we describe the model by $(\lambda_\cdot,\pi)$ instead of $(\lambda_1,\dots,\lambda_K)$, the likelihood is

$$L(\lambda_\cdot,\pi)=\underbrace{\frac{\lambda_\cdot^{\,n}e^{-\lambda_\cdot}}{n!}}_{L_1(\lambda_\cdot)\ =\ \text{Poisson for the total}}\times\underbrace{\frac{n!}{\prod_i y_i!}\prod_i\pi_i^{y_i}}_{L_2(\pi)\ =\ \text{multinomial for the split}} .$$

Is it OK to switch to $(\lambda_\cdot,\pi)$? Yes, because the change is one-to-one. Going forward, $\lambda_\cdot=\sum\lambda_i$ and $\pi_i=\lambda_i/\lambda_\cdot$. Going back, $\lambda_i=\lambda_\cdot\pi_i$. Every vector of rates corresponds to exactly one (total, shares) pair and the other way round. It's the same model with different coordinates, and the maximum is the same point either way (MLEs are invariant under reparametrisation).

Checking by direct calculation. Put $\lambda_i=\lambda_\cdot\pi_i$ straight into the Poisson likelihood:

$$\prod_{i}\frac{(\lambda_\cdot\pi_i)^{y_i}e^{-\lambda_\cdot\pi_i}}{y_i!} =\frac{\lambda_\cdot^{\sum y_i}\;e^{-\lambda_\cdot\sum\pi_i}}{\prod_i y_i!}\prod_i\pi_i^{y_i} =\frac{\lambda_\cdot^{\,n}\,e^{-\lambda_\cdot}}{\prod_i y_i!}\prod_i\pi_i^{y_i} =\frac{\lambda_\cdot^{\,n}e^{-\lambda_\cdot}}{n!}\cdot\frac{n!}{\prod_i y_i!}\prod_i\pi_i^{y_i}.$$

Two small facts do all the work. $\sum y_i=n$ collects all the $\lambda_\cdot$'s into $\lambda_\cdot^n$. $\sum\pi_i=1$ collects all the exponentials into $e^{-\lambda_\cdot}$. On the log scale, the product becomes a sum:

$$\ell(\lambda_\cdot,\pi)=\underbrace{\big(n\log\lambda_\cdot-\lambda_\cdot\big)}_{\ell_1:\ \text{only }\lambda_\cdot}+\underbrace{\sum_i y_i\log\pi_i}_{\ell_2:\ \text{only }\pi}+\text{const}.$$

3.5 Why a factorised likelihood can be maximised piece by piece

Say you want to maximise $f(a)+g(b)$. If any $a$ can be combined with any $b$, the answer is obvious: take the best $a$ for $f$ and the best $b$ for $g$. Proof: for every allowed $(a,b)$,

$$f(a)+g(b)\le f(\hat a)+g(\hat b),$$

and the pair $(\hat a,\hat b)$ is itself allowed. The last part is the whole point. It requires that the parameter space is a product, $\Theta=\Theta_a\times\Theta_b$. That's the definition of variationsuafhængighed (variation independence).

Factorisation alone is not enough. Suppose the model also required $a=b$. Then $(\hat a,\hat b)$ might not be allowed, and you'd have to compromise between $f$ and $g$. So you need both: (1) the likelihood factorises, and (2) the parameters are variation independent.

Another way to see it: the score equations separate. $\partial\ell/\partial\lambda_\cdot$ only involves $\ell_1$, and $\partial\ell/\partial\pi$ only involves $\ell_2$. All the mixed second derivatives are 0, so the Fisher information is block diagonal. The estimates of $\lambda_\cdot$ and $\pi$ don't influence each other, even in their uncertainty.

Maximising each piece:

  • $\ell_1$: $\dfrac{n}{\lambda_\cdot}-1=0\Rightarrow\boxed{\hat\lambda_\cdot=n}$. The fitted total always equals the observed total.
  • $\ell_2$: this is the multinomial log-likelihood, so $\hat\pi$ = the multinomial MLE.

So the Poisson fit gives $\hat\lambda_i=n\hat\pi_i$, and $\hat\pi_i=\hat\lambda_i/n$ is exactly the multinomial answer.

3.6 With a log-linear model: why it has to be a free intercept

So far the $\lambda_i$'s were completely free. In practice we restrict them with $\log\lambda_i=\beta_0+x_i'\beta$. Does variation independence still hold? Compute total and shares:

$$\lambda_i=e^{\beta_0}e^{x_i'\beta}\quad\Longrightarrow\quad \pi_i=\frac{e^{\beta_0}e^{x_i'\beta}}{e^{\beta_0}\sum_j e^{x_j'\beta}}=\frac{e^{x_i'\beta}}{\sum_j e^{x_j'\beta}},\qquad \lambda_\cdot=e^{\beta_0}\underbrace{\textstyle\sum_j e^{x_j'\beta}}_{S(\beta)} .$$
  • $e^{\beta_0}$ cancels in $\pi$, so the shares depend only on $\beta$. That's the multinomial log-linear model with the same $\beta$.
  • For any $\beta$, choosing $\beta_0=\log c-\log S(\beta)$ gives $\lambda_\cdot=c$ for any $c>0$. So $\beta_0$ controls the total and $\beta$ controls the shares, and every combination is possible.

Cleanest version of the argument (profile likelihood). Switch from $(\beta_0,\beta)$ to $(\lambda_\cdot,\beta)$, which is one-to-one. Then

$$L(\lambda_\cdot,\beta)=L_1(\lambda_\cdot)\cdot L_{\text{multinom}}\big(\pi(\beta)\big),\qquad\lambda_\cdot\in(0,\infty)\text{ for every }\beta .$$

For every fixed $\beta$, the best $\lambda_\cdot$ is $n$, whatever $\beta$ is. Plug that in:

$$\max_{\lambda_\cdot}L(\lambda_\cdot,\beta)=\underbrace{L_1(n)}_{\text{constant}}\cdot L_{\text{multinom}}\big(\pi(\beta)\big).$$

So the Poisson profile likelihood for $\beta$ is the multinomial likelihood times a constant. Same maximiser $\hat\beta$, same curvature (standard errors), same likelihood ratios.

Without an intercept, it breaks. Three cells, $\log\lambda_i=\beta x_i$ with $x=(0,1,2)$ and no intercept: $$\lambda_\cdot=1+e^{\beta}+e^{2\beta},\qquad \pi=\frac{(1,\,e^\beta,\,e^{2\beta})}{1+e^\beta+e^{2\beta}}.$$ One parameter controls both the total and the shares, so the parameter space is not a product. Getting $\lambda_\cdot=n$ pulls $\beta$ one way, the best split pulls it another. The Poisson MLE settles on a compromise, and its $\hat\pi$ is not the multinomial MLE.

Technical point: "free intercept" really means that the constant vector $(1,\dots,1)$ lies in the column space of the design matrix. ~ door - 1 is fine too, because the three door dummies add up to the constant column. It also shows up in the score equation for $\beta_0$: $\sum_i(y_i-\hat\lambda_i)=0$, i.e. $\hat\lambda_\cdot=n$.

3.7 The tests are identical too, and an example

A likelihood ratio test compares $\ell$ under $H_0$ and $H_1$. Both models have a free intercept, so both have $\hat\lambda_\cdot=n$. The $\ell_1$ piece is the same number in both and cancels in the difference:

$$G^2=2\big[\ell_{H_1}-\ell_{H_0}\big]=2\big[\ell_{2,H_1}-\ell_{2,H_0}\big]=\text{multinomial LRT}.$$

Rats, $(23,36,31)$, $n=90$:

$H_1$: ~ door(23, 36, 31)90(.256, .400, .344)(23, 36, 31)/90 ✓
$H_0$: ~ 1(30, 30, 30)90(1/3, 1/3, 1/3)(1/3, 1/3, 1/3) ✓

3.8 The same idea, used again later

General rule: every total that is fixed by design needs its own free parameter in the model.

  • Homogeneity (fixed row totals $n_i$): each row is its own multinomial and needs its own free $\lambda_{i\cdot}$. That's why the row main effect must always be in the model. It guarantees $\hat\lambda_{i\cdot}=n_i$.
  • Logistic regression via log-linear models: for each $(X=i,Z=k)$ the pair (Y=0, Y=1) is a binomial with total $\lambda_{i\cdot k}$. The X:Z term provides those free totals.
The two-sentence answer: A Poisson likelihood is always (likelihood for the total) × (multinomial likelihood for the split), because the total depends only on $\lambda_\cdot$ and the split only on $\pi$. With a free intercept, total and split can vary independently, so the two factors are maximised separately, and the Poisson fit gives the multinomial estimates and tests.
Why does the factorisation in 3.4(a) give us nothing on its own, and what extra fact do we need?
$P(Y=y)=P(N=n)P(Y=y\mid N=n)$ holds for every distribution. What's special about Poisson is that the first factor depends only on $\lambda_\cdot$ and the second only on $\pi$. On top of that, we need $\lambda_\cdot$ and $\pi$ to be variation independent, which the free intercept provides.
In 3.3, where exactly did we use that $y_1+\dots+y_K=n$?
Twice: to drop "$N=n$" from the numerator, and to share $\lambda_\cdot^{\,n}$ out as $\lambda_\cdot^{y_1}\cdots\lambda_\cdot^{y_K}$, which turns each $\lambda_i^{y_i}$ into $(\lambda_i/\lambda_\cdot)^{y_i}$.
You fit a Poisson log-linear model and the fitted values sum to 87, but $n=90$. What's wrong?
The constant isn't in the column space of the design matrix, i.e. no free intercept. With one, the score equation $\sum(y_i-\hat\lambda_i)=0$ forces $\hat\lambda_\cdot=n$.
A study fixes 200 men and 300 women in advance and records smoker yes/no. Which term must always be in the log-linear model?
The sex main effect. Each row is its own binomial with a fixed total, so it needs its own free total. That gives $\hat\lambda_{\text{men}\cdot}=200$ and $\hat\lambda_{\text{women}\cdot}=300$.

4Log-linear models: Poisson vs multinomial version

$$\text{Poisson: }\log\lambda_i=\beta_0+x_i'\beta\qquad\qquad \text{Multinomial: }\log\pi_i=\beta_0^*+x_i'\beta$$

Since $\pi_i = \lambda_i/\lambda_\cdot$, taking logs gives $\log\pi_i = (\beta_0-\log\lambda_\cdot) + x_i'\beta$. So:

  • All the slopes $\beta$ are the same in both versions. These are the parameters we interpret.
  • Only the intercept differs. $\beta_0^* = -\log\sum_i e^{x_i'\beta}$ is just a normalising constant that makes the probabilities sum to 1.
Is the intercept from glm(..., poisson) interesting for a contingency table?
Usually not. It only reflects the total sample size, the "how many" part. The information about association sits in the other $\beta$'s, especially the interactions.

51-D example: rats, doors, and Pearson's χ²

90 rats choose between 3 doors: counts $(23, 36, 31)$. Is there a preference? $H_0: \pi_1=\pi_2=\pi_3=1/3$.

Model with door 1 as reference: $\log\lambda_i = \beta_0+\beta_1 x_{i1}+\beta_2x_{i2}$, so

$$\lambda_1=e^{\beta_0},\quad \lambda_2=e^{\beta_0+\beta_1},\quad\lambda_3=e^{\beta_0+\beta_2}\quad\Rightarrow\quad \frac{\lambda_2}{\lambda_1}=e^{\beta_1},\ \frac{\lambda_3}{\lambda_1}=e^{\beta_2}.$$

"No preference" is the same as $\beta_1=\beta_2=0$. Under $H_0$, every expected count is $90/3 = 30$.

Pearson's χ² compares observed and expected counts:

$$X^2=\sum_i\frac{(Y_i-e_i)^2}{e_i}=\frac{(23-30)^2+(36-30)^2+(31-30)^2}{30}=2.867,\qquad X^2\overset{as}{\sim}\chi^2_{K-1}=\chi^2_2.$$
The slides' big derivation, in one sentence: if you do a score test of $\beta_1=\beta_2=0$ in the Poisson model (score $U=X'(y-\lambda)$, information $X'\mathrm{diag}(\lambda)X$, profile out the nuisance $\beta_0$ with the effective information), the algebra collapses to exactly Pearson's $X^2$. So the "old" χ²-test is a score test from likelihood theory.

The full model here is saturated (3 parameters, 3 cells). Fitted values equal the data, $\hat\beta_0=\log 23$, $\hat\beta_1=\log(36/23)$, and so on.

Why are there 2 degrees of freedom and not 3?
3 cells, but the probabilities must sum to 1 (equivalently, the intercept is estimated even under $H_0$). The test restricts $\beta_1,\beta_2$, which is 2 parameters. $2.867$ is well below the 5% critical value of $\chi^2_2$ (5.99), so there's no evidence of a door preference.

62-D tables: independence (and homogeneity)

If X and Z are independent, then $\pi_{ij}=\pi_{i\cdot}\pi_{\cdot j}$. Take logs:

$$\log\lambda_{ij}=\log n+\log\pi_{i\cdot}+\log\pi_{\cdot j}\;=\;\alpha_i+\gamma_j .$$
Key translation: independence = additive model = no X:Z interaction. In R you compare Freq ~ X + Z against the saturated Freq ~ X * Z.

Under $H_0$ the fitted values are the familiar $\hat\lambda_{ij}=\dfrac{y_{i\cdot}\,y_{\cdot j}}{n}$ (row total × column total / n). Two test statistics:

$$G^2 = 2\sum_{ij} y_{ij}\log\frac{y_{ij}}{\hat\lambda_{ij}}\ \ (\text{LRT / deviance}),\qquad X^2=\sum_{ij}\frac{(y_{ij}-\hat\lambda_{ij})^2}{\hat\lambda_{ij}}\ \ (\text{score} = \text{Pearson})$$

Both are approximately $\chi^2_{(I-1)(J-1)}$. The df comes from $IJ$ free cells minus $I+J-1$ parameters in the additive model.

Independence vs homogeneity: different question, same test

  • Independence: sample $n$ people, record both X and Z. Row totals are random.
  • Homogeneity: choose $n_i$ people from each group in advance (row totals fixed by design). Ask if the distribution over Z is the same in every group.

The likelihood factorises into a "row totals" part times a "within-row" part, and the row part is maximised identically under $H_0$ and the alternative. So the LRT is identical. In the Poisson model, the row effects make sure $\hat\lambda_{i\cdot}=n_i$. That's why the model must always include the row main effect, even if it's "uninteresting".

Influenza table: 0, 1, 2 vaccinations with rows (24, 289), (9, 100), (13, 565). What's the expected number of flu cases among those with 0 vaccinations under independence?
$\hat\lambda = \frac{313\cdot 46}{1000} = 14.4$. Observed is 24, much more than expected. Df $=(3-1)(2-1)=2$.

73-D tables: conditional independence

$X \perp\!\!\!\perp Z \mid Y$ means: once you know Y, Z tells you nothing extra about X. Formally,

$$P(X=x,Z=z\mid Y=y)=P(X=x\mid Y=y)\,P(Z=z\mid Y=y).$$
Watch out: conditional independence does not imply marginal independence. Example: shoe size and reading skill are related in children, but independent given age.

General rule for going from intensities to probabilities: normalise $\lambda$ over the relevant cells, e.g. $P(X=i\mid Y=j)=\lambda_{ij\cdot}/\lambda_{\cdot j\cdot}$.

Working through the algebra, conditional independence is equivalent to $\lambda_{ijk}=\lambda_{ij\cdot}\lambda_{\cdot jk}/\lambda_{\cdot j\cdot}$. Take logs:

$$\log\lambda_{ijk}=f_{XY}(i,j)+f_{YZ}(j,k)\qquad\Longleftrightarrow\qquad X\perp\!\!\!\perp Z\mid Y.$$

In R: Freq ~ X*Y + Y*Z. There's no X:Z and no X:Y:Z term. Test it against the saturated model (deviance or sum(resid(fit, "pearson")^2)), just like in the Boliga example.

In Freq ~ Sold*Postal + Postal*Type, which conditional independence is assumed?
Postal code is the shared variable, so: Sold $\perp\!\!\!\perp$ Type $\mid$ Postal. Within each postal code, whether a house sells quickly doesn't depend on house type.

8What interaction terms actually mean: odds ratios

For binary variables, there's a clean ladder of interpretations:

TermMeaning
main effect $\beta^X$difference in log-intensity, a log-odds
2-way $\beta^{XZ}$difference of log-odds = log odds ratio
3-way $\beta^{XYZ}$difference of log odds ratios

2×2 table, $\log\lambda_{ij}=\beta_0+\beta^X i+\beta^Z j+\beta^{XZ}ij$:

$$e^{\beta^{XZ}}=\frac{\lambda_{11}\lambda_{00}}{\lambda_{10}\lambda_{01}}=\text{OR}\qquad(\beta^{XZ}=0\iff \text{OR}=1\iff\text{independence}).$$

2×2×2 table (saturated): the X–Z odds ratio within layer $Y=j$ is

$$\log\text{OR}_{XZ\mid Y=j}=\beta^{XZ}+\beta^{XYZ}j .$$
Two restrictions that are easy to confuse:
  • $\beta^{XYZ}=0$: the odds ratio is the same in both layers, but can be ≠ 1 (association, just constant).
  • $\beta^{XZ}=\beta^{XYZ}=0$: the odds ratio is 1 in both layers, which is conditional independence.
"No three-way interaction" is the weaker assumption.
A fitted 2×2 log-linear model gives $\hat\beta^{XZ}=0.69$. Explain it to a non-statistician.
$e^{0.69}\approx 2$: the odds of X=1 are about twice as high when Z=1 as when Z=0. So X and Z are positively associated.

9Graphical models, and the link to logistic regression

Graphs

Draw one node per variable. Missing edge = conditional independence. The model gets one term per maximal clique (group of nodes that are all connected to each other):

$$\log\lambda_{\mathbf i}=\sum_{C\in\mathcal C(G)} f_C(\mathbf i_C).$$

Example X — Y — Z: cliques $\{X,Y\},\{Y,Z\}$ give $f_{XY}+f_{YZ}$, which is $X\perp\!\!\!\perp Z\mid Y$. Example with A, B, C fully connected, C—D, D—E: $f_{ABC}+f_{CD}+f_{DE}$.

Not every log-linear model is graphical. "All two-way interactions, no three-way" (X*Y + X*Z + Y*Z) has a triangle graph. But the triangle is a clique $\{X,Y,Z\}$, and the graphical model would then include the 3-way term too.

From log-linear to logistic regression

Let Y be binary. Within a fixed (X=i, Z=k):

$$\operatorname{logit}P(Y=1\mid X=i,Z=k)=\log\lambda_{i1k}-\log\lambda_{i0k}.$$

Take the model with all two-way interactions and subtract. Every term without Y cancels:

$$\operatorname{logit}(p_{ik})=\gamma_0+\gamma^X_i+\gamma^Z_k .$$
Takeaway: the log-linear model X*Y + X*Z + Y*Z gives the same estimates as the logistic regression Y ~ X + Z. The X:Z term plays the role of the "free intercept" for each (i,k) combination. It's the Poisson trick again, this time Poisson → binomial. Rule of thumb: Y-terms in the log-linear model become the logistic model's terms, minus the Y.
Which log-linear model matches the logistic regression Y ~ X * Z (with X:Z interaction)?
You need a Y:X:Z term (which becomes the X:Z term after dropping Y), plus X*Z for the free totals. That's the saturated model Freq ~ X*Y*Z.

Summary

  • Counts in a table → Poisson GLM on $\log\lambda$. The Poisson trick guarantees the same answers as the multinomial model, as long as there's a free intercept (and free row totals when they're fixed by design).
  • Association hypotheses = removing interaction terms. Test with deviance ($G^2$) or Pearson ($X^2$, which is a score test).
  • Independence ⇔ no 2-way term. Conditional independence ⇔ no terms linking X and Z. Interactions are (log) odds ratios.

Why is $P(Y=y,\,N=n)=P(Y=y)$? (Section 3.3: $P(Y=y\mid N=n)=\frac{P(Y=y,\,N=n)}{P(N=n)}=\frac{P(Y=y)}{P(N=n)}$.) Explain it very concretely with set notation.
Tutor

Short version: the event "$Y=y$" is a subset of the event "$N=n$". When one set lies inside another, their intersection is just the smaller set. Below, step by step.

1A comma means "and" means intersection

Every probability is a probability of a set of outcomes (an event). Name the two events:

$$A=\{Y=y\}=\{\text{outcomes where the count vector is exactly }y\},\qquad B=\{N=n\}=\{\text{outcomes where the total is }n\}.$$

The comma in $P(Y=y,\,N=n)$ means "both happen", which is the intersection:

$$P(Y=y,\,N=n)=P(A\cap B).$$

So the question is really: why is $A\cap B=A$?

2A tiny concrete example

Take $K=2$ cells, observed counts $y=(2,1)$, so $n=2+1=3$. An outcome is a pair $(Y_1,Y_2)$ of counts. Let's list the sets explicitly:

$$A=\{Y=(2,1)\}=\{(2,1)\}$$ $$B=\{N=3\}=\{Y_1+Y_2=3\}=\{(0,3),\,(1,2),\,(2,1),\,(3,0)\}$$

Now intersect, i.e. keep the outcomes that are in both sets:

$$A\cap B=\{(2,1)\}\cap\{(0,3),(1,2),(2,1),(3,0)\}=\{(2,1)\}=A .$$

The picture shows every possible outcome as a dot. $B$ is the diagonal where $Y_1+Y_2=3$. $A$ is the single orange dot, and it lies on the diagonal. Asking "is it in $A$ and in $B$?" picks out the same dot as just asking "is it in $A$?"

3The general argument: $A\subseteq B$

The key is that $N$ is not a new random variable. It is calculated from $Y$: $N=Y_1+\dots+Y_K$. So:

Take any outcome in $A$. There, $Y_1=y_1,\dots,Y_K=y_K$.
So for that outcome $N=Y_1+\dots+Y_K=y_1+\dots+y_K=n$.
So the outcome is also in $B$.

Every element of $A$ is in $B$, which means $A\subseteq B$. A basic set rule:

$$A\subseteq B\quad\Longrightarrow\quad A\cap B=A\quad\Longrightarrow\quad P(A\cap B)=P(A).$$

That's exactly $P(Y=y,\,N=n)=P(Y=y)$.

In everyday terms: "I rolled a 4 and I rolled an even number" is the same event as "I rolled a 4", because 4 is already even. Adding "and even" filters out nothing. In the same way, adding "and the total is $n$" to "the counts are exactly $y$" filters out nothing: if you know every count, you already know the total.

4Why the slides require $\sum y_i=n$

The argument used $y_1+\dots+y_K=n$. What if that fails? Take $y=(2,2)$ but $n=3$:

$$A=\{(2,2)\},\qquad B=\{(0,3),(1,2),(2,1),(3,0)\},\qquad A\cap B=\varnothing .$$

Then $A$ and $B$ don't overlap, and $P(Y=y\mid N=n)=0$. That's obviously right: if the total is 3, the counts can't be $(2,2)$. So the formula is only interesting when $\sum y_i=n$, which is why the slides assume it.

Putting it back into the formula

$$P(Y=y\mid N=n)=\frac{P(A\cap B)}{P(B)}=\frac{P(A)}{P(B)}=\frac{P(Y=y)}{P(N=n)} .$$

The numerator is now just a product of independent Poisson probabilities, which we can write down. In the example, conditioning on $N=3$ means "zoom in on the blue diagonal and rescale so its probabilities sum to 1". The conditional probability of $(2,1)$ is that dot's share of the diagonal's total probability.

With $K=3$ cells and $n=2$: list $B=\{N=2\}$. Is $A=\{Y=(1,0,1)\}$ a subset of $B$? What is $A\cap B$?
$B=\{(2,0,0),(0,2,0),(0,0,2),(1,1,0),(1,0,1),(0,1,1)\}$, which has 6 outcomes. $(1,0,1)$ sums to 2, so it's in $B$. That means $A\subseteq B$ and $A\cap B=A=\{(1,0,1)\}$.
Is it also true that $P(N=n,\,Y=y)=P(N=n)$? Why or why not?
No. It would need $B\subseteq A$, but $B$ contains many outcomes besides $y$ (e.g. $(0,3)$). Knowing the total doesn't tell you the individual counts. The information only flows one way: $Y$ determines $N$, not the other way round.

3Why the math allows it

Your intuition was probably: "the overall OR must be some kind of average of the department ORs, so it can't lie outside their range." That's false for odds ratios. Summing over Dept doesn't average the ORs. It mixes the counts:

$$\lambda_{ag\cdot}=\sum_{d}\lambda_{agd},\qquad OR_{\text{marginal}}=\frac{\lambda_{\text{adm},M,\cdot}\;\lambda_{\text{rej},F,\cdot}}{\lambda_{\text{rej},M,\cdot}\;\lambda_{\text{adm},F,\cdot}} .$$

How much each department weighs in each of the four sums depends on how many men vs women applied there. When those weights differ between men and women, the marginal OR picks up the Dept–Gender and Dept–Admit associations as well.

When is it safe to sum over Dept (collapsibility)? The marginal Admit–Gender OR equals the conditional ones (when those are all equal) if Dept is conditionally independent of Admit or of Gender, i.e. if the model has no Admit:Dept term or no Gender:Dept term. Here both associations are huge, so collapsing is not allowed.

Link to the lecture (section 7): "conditional independence does not imply marginal independence". UCB is the classic example. The A2 model Admit*Dept + Gender*Dept says Admit ⊥⊥ Gender | Dept, which fits reasonably (apart from department A). But marginally, Admit and Gender are strongly dependent (OR = 1.84), and the reason is the shared variable Dept, which connects them in the graph Admit — Dept — Gender.

1The bug: predict() returns $\log\hat\lambda$ by default

For a GLM, predict() by default returns values on the link scale (type = "link"). With a log link, that's $\log\hat\lambda$, not $\hat\lambda$. So your loop sums logarithms of the fitted counts:

$$\sum_d \log\hat\lambda_{agd}\quad\text{instead of}\quad\sum_d\hat\lambda_{agd}.$$

I ran it. You get a "table" of about $(28.7,\ 32.9,\ 25.1,\ 28.6)$ and an OR of 0.997, which is meaningless. The cells should add up to $n = 4526$. Fix:

hat_lambda_temp_11[i] <- predict(fit_all_veksel, newdata = df_temp_11, type = "response")

Quick sanity check: fitted counts in a Poisson model with an intercept must sum to $n$ (the Poisson trick, section 3.6). If your fitted table doesn't sum to 4526, something is wrong.

2After the fix: you get exactly 1.84 again. Why?

With type = "response", the fitted table is exactly the observed one: (1198, 1493, 557, 1278), so the OR is 1.84. That's not a coincidence.

Recall the score equations for a Poisson GLM: $U(\beta)=X'(y-\hat\lambda)=0$. There's one equation per column of the design matrix. fit_all_veksel contains the Admit:Gender term, so (together with the main effects) the design matrix contains indicators for each Admit×Gender combination. The score equation for such a column says:

$$\sum_{d}\big(y_{agd}-\hat\lambda_{agd}\big)=0\quad\Longleftrightarrow\quad\underbrace{\hat\lambda_{ag\cdot}}_{\text{fitted margin}}=\underbrace{y_{ag\cdot}}_{\text{observed margin}}.$$
General rule for log-linear models: every margin that matches a term in the model is fitted exactly. A model with Admit*Gender reproduces the Admit×Gender table perfectly. So its fitted marginal OR is always the observed 1.84. The calculation is valid, it just tells you nothing new.

It's the same mechanism as the intercept forcing $\hat\lambda_\cdot = n$, and the row effect forcing $\hat\lambda_{i\cdot}=n_i$ for homogeneity.
